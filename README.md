## 历史版本：右上方格起终点与统一轨迹算法（2026-10-11）

起点、终点目标都是附件右上方格中心 `(1.7, 1.7)` 米；方格范围为 `[1.4, 2.0] × [1.4, 2.0]`。出发朝西，结束时由北向右转入格朝东。再开始一圈时，仅在方格内通过整车旋转检查后调向。旧版把起终点误设在方格左侧车道 `(1.1, 1.7)`，并要求最后向左回到那里，与附件中的方格不符。

所有移动路径现在共用一个连续曲率求解器、弧长速度包络与跟踪方法。统一到达逻辑会核算当前指令是否能在到达范围和1.2秒时间预算内完成朝向修正；无法完成时停车并检查完整旋转空间，防止极低速爬出目标范围。规划器先粗搜再细化；数值残差计算保留同样的高斯积分，减少临时数组。最终轨迹仍逐段核验整车扫掠、未知网格及灯柱。Nav2 平滑路径提前朝侧向目标偏折时，保留经过实时代价地图与整车扫掠核验的初始车道切向，再连接弯道。长直线入口从道路矩形推导中心与切向，连续接入中心线，避免把小航向误差延续整段；不按路点名或固定坐标切换。静止末端航向反馈统一调整，并保持既有角速度及加速度上限。规划失败后等待新版本代价地图再重试，最多三次；代价地图不更新则五秒内故障停车，防止清障后在同一旧网格上耗尽所有重试。定位在收到每条有效轮速后立即发布，并为轮速保留短队列；源时间、IMU、相机及轮速过期保护不变，真实断流不外推。场景起终点、目标朝向与合法区域集中于 `config/patrol_task.json`，世界生成、定位初值、SLAM 坐标变换、导航和结束检查读取同一配置。

直线巡航上限 0.26 m/s，角速度上限 0.65 rad/s。弯道按曲率、曲率变化、加速度与制动距离限速；终点制动考虑 0.25 s 命令延迟。线角速度同步改变；红灯、观察、障碍和消息新鲜度保护保持启用。

本次复测：7 个独立用例中的 8 圈物理仿真（建图、新地图、动态障碍、传感器扰动、暗光、出生偏移、同一世界连续两圈）。均核对实际车身、全部 17 路点和 8 次确认观察；目标仍为相机实测 10 人和 3 张不同车牌。离线还检查场景平移、旋转、反射、不同转角/长度、未知障碍拒绝及速度约束。这些离线变换不等于已完成任意新场景的实测。

## 技术链与语言

相机/激光/轮速/实际云台编码器 → 图像时间对齐 → YOLO11s + OCR → 多帧及双角度确认 → 定位质量与障碍保护 → 路点状态机与限幅 PID → C++ 运动管理 → Gazebo 差速底盘。

- Python 负责视觉、定位融合、巡检状态机、ROS 适配与独立验收。
- C++17 负责运动管理器与原生 Gazebo 信号灯系统。
- ROS 2 的话题/时间戳连接模块；SDF、XML、YAML 描述场景、DDS 和导航参数。
- 已安装 Nav2 / SLAM Toolbox 提供规划和建图接口；当前通过的是固定地图巡检，未证明任意地图自主导航。

### 定位与输入验证

图像与轮速、实际云台编码器按源时间配对；只在允许时间间隔内插值，不外推、不跨断流补值。历史地面标线校正传播至当前轮速位置。非有限值、错误时间戳、坏图像尺寸、过期消息不能刷新有效导航证据。云台转动或侧向观察时不做前向地面校正。

### 视觉与传输

运行 `src/community_demo/models/perception/yolo11s-comparison.pt`，CUDA 推理，输入尺寸 960，检测置信度阈值 0.35、IoU 阈值 0.45，处理目标 10 Hz，OCR 间隔 0.6 秒。原始相机用于识别；标注预览使用压缩话题，原始标注图仅在事件或 2 Hz 发布。

发送和接收 UDP socket 通过 `tools/fastdds_udp.xml` 请求 4 MiB 缓冲，主机原有上限允许该值，未改系统参数。通过 `tools/ros_transport.sh` 加载默认参与者配置。接口依据：[Fast DDS UDP 官方文档](https://fast-rtps.docs.eprosima.com/en/2.14.x/fastdds/transport/udp/udp.html)。

### 控制与等待

直线速度上限 0.26 m/s，弯前限速；检查当前与预测完整车身道路轮廓和灯柱净空。短暂源新鲜度丢失时底盘停车并保持观察云台朝向，实际距离失配时才回正校正。道路恢复只允许短距离安全前进，不能恢复则报错。

绿灯通行需要连续新鲜相机证据和足够剩余时间下界。相位只从相机观察的合法灯色边沿学习；仿真真值只供独立评分器使用。车牌提前结束需两次高置信 OCR、至少 6 帧、1.8 秒观察和 0.8 秒证据安静期，不能用未确认、过早、过期或错视角反馈放行。
