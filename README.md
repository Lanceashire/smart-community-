# AIC 智慧社区：巡检导航与视觉识别

基于用户提供的复赛资料和已有 ROS/Gazebo 工程，完成固定地图的单圈巡检、相机红绿灯停行、人员统计、车牌 OCR 和终端输出。机器人采用有效的差速驱动与实际云台编码器。本次优化在现有 `aic-development` 容器完成，未重建容器，未重训模型。

## 技术链与语言

相机/激光/轮速/实际云台编码器 → 图像时间对齐 → YOLO11s + OCR → 多帧及双角度确认 → 定位质量与障碍保护 → 路点状态机与限幅 PID → C++ 运动管理 → Gazebo 差速底盘。

- Python 负责视觉、定位融合、巡检状态机、ROS 适配与独立验收。
- C++17 负责运动管理器与原生 Gazebo 信号灯系统。
- ROS 2 的话题/时间戳连接模块；SDF、XML、YAML 描述场景、DDS 和导航参数。
- 已安装 Nav2 / SLAM Toolbox 提供规划和建图接口；当前通过的是固定地图巡检，未证明任意地图自主导航。

### 定位与输入验证

图像与轮速、实际云台编码器按源时间配对；只在允许时间间隔内插值，不外推、不跨断流补值。历史地面标线校正传播至当前轮速位置。非有限值、错误时间戳、坏图像尺寸、过期消息不能刷新有效导航证据。云台转动或侧向观察时不做前向地面校正。

### 视觉与传输

运行 `src/community_demo/models/perception/yolo11s-comparison.pt`，CUDA 推理，输入尺寸 960，检测置信度阈值 0.35、IoU 阈值 0.45，处理目标 10 Hz，OCR 间隔 0.6 秒。原始相机用于识别；标注预览使用压缩话题，原始标注图仅在事件或 2 Hz 发布。

发送和接收 UDP socket 通过 `tools/fastdds_udp.xml` 请求 4 MiB 缓冲，主机原有上限允许该值，未改系统参数。通过 `tools/ros_transport.sh` 加载默认参与者配置。接口依据：[Fast DDS UDP 官方文档](https://fast-rtps.docs.eprosima.com/en/2.14.x/fastdds/transport/udp/udp.html)。

### 控制与等待

直线速度上限 0.24 m/s，弯前限速；检查当前与预测完整车身道路轮廓和灯柱净空。短暂源新鲜度丢失时底盘停车并保持观察云台朝向，实际距离失配时才回正校正。道路恢复只允许短距离安全前进，不能恢复则报错。

绿灯通行需要连续新鲜相机证据和足够剩余时间下界。相位只从相机观察的合法灯色边沿学习；仿真真值只供独立评分器使用。车牌提前结束需两次高置信 OCR、至少 6 帧、1.8 秒观察和 0.8 秒证据安静期，不能用未确认、过早、过期或错视角反馈放行。

## 本机运行

在本工程挂载的现有容器工作目录中：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
source tools/ros_transport.sh
source tools/vision_env.sh
bash tools/launch_full.sh gui:=true paused:=false
```

自动验收使用 `gui:=false`，仍保留真实相机渲染。重启后旧容器显示认证挂载丢失时，可在宿主机工程目录运行 `bash tools/start_existing_container.sh aic-development`。

完整比较流水线依赖本机保存的旧版密集基准、原世界哈希和故意错误帧号反例输入。输入齐备并停止其他演示世界后：

```bash
python3 tools/run_complete_acceptance.py --extended --output validation/optimization-2026-10-06
```

先保存已有输出，不能覆盖历史成功/失败证据。仓库 README 提供汇总结果，完整原始验收输入和逐帧证据保留本机；仅克隆仓库不能单独复现全部历史比较步骤。

## 证据范围与待办

最终成功 11 圈不包含失败/中断圈和开发探针。时间超限、初始灯色接收顺序、噪声下观察重试、拐角恢复及绿灯覆盖不足的失败全部留本机；覆盖不足后补充早绿启动情形，保留晚绿情形，并完整重新实跑。
