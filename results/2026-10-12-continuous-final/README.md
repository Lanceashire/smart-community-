# 连续转弯剩余缺陷修复（2026-10-12）

综合验收 566/566 通过；8 圈真实 Gazebo 测试。另有 366 项 Python 离线检查、19 项 C++ 单元测试和7项实际控制器隔离测试。

## 缺陷与修复

| 缺陷 | 原因 | 修改与复测 |
|---|---|---|
| 两圈在左侧识别结束后各停约 0.3 秒 | 到观察点后才请求下一段 Nav2 路径 | 识别期间预请求并在后台计算下一段曲线，交接时从实测位置构造短切线连接，用新鲜代价地图重新认证整条路径。两圈相同完整转弯窗口停车均为 0。 |
| 管理器瞬间减速约 5.01 m/s²，超过 0.5 门槛 | 新指令源时间比本地时钟提前 1 ms，却先覆盖了仍有效的旧指令 | 按源时间暂存新指令，其时刻到达后再切换；旧指令过期即停车。最新两圈最大值分别 0.500000、0.500000 m/s²，浮点误差按原检查处理。 |
| 偏移出生后，中部弯无法满足原 0.025 rad 朝向收敛条件 | 首帧 IMU 硬对齐名义正西，车道线的朝向修正被关闭 | 用初始有效车道线多帧一致观测校准地图与 IMU 朝向，保留 IMU 的源时间增量。前10秒后最大误差 2.035° → 0.073°；完整圈初始误差仍原样记录，原转弯门槛通过。 |

## 实现边界

- 预请求的起点是任务预定观察点，只作 Nav2 搜索参考；真正发布路径时从实时实测位姿生成短切线连接，检查整车扫掠、障碍、未知格和地图时效。过期缓存、错圈缓存和新增障碍的反例均测过。
- 新指令不允许提前执行，也不延长旧指令寿命；紧急停车、无有效指令停车和原指令仲裁优先级仍有效。极远未来或乱序旧指令不能污染缓存。
- 朝向校准只在首次有效地面配准后的六秒窗口内，要求三帧一致、可观测性改善和修正幅度上限；使用真实相机地面车道线与编码器角度，不读取 Gazebo 真值作为控制输入。
- 传感器扰动圈的源时刻覆盖率仍接近98%门槛，固定2秒黑屏/丢失占据较大比例；即使本轮通过，也不能称充足裕量。完整原始分母与失败记录保留。
- 原道路边界、2 cm 实测直线偏移、6 cm 定位误差、5 cm 灯柱净空、98% 位姿源覆盖率、8 Hz 视觉和150 ms图像P95时效门槛保留。
- 转弯窗口计算到实际朝向收敛，包含识别开始后的剩余转向；沿用上一版完整转弯检查，没有通过缩短窗口隐藏停顿。

## 尚不能称为完美的范围

识别证据不足仍会停车补采，红灯和障碍仍会等待；修复的是无效停顿，并不承诺任意场景全程不停。已知图库、固定赛道仿真通过，不代表实车、陌生人物、任意初始位姿或长期漂移。初始视觉校准依赖可见车道线，六秒后不会继续用模糊画面修改全局朝向。持续占道时主动绕行仍未验证。整体圈时受红灯相位影响，不能仅凭两次录像宣称圈速提高。

## 可复现性

本次每个最终场景记录同一份源码和实际加载的 C++ 控制器动态库哈希。source.zip 包含源码、已验证地图及动态库，重建以源码为准。evidence.zip 包含全部JSON、路径与检测图、测试结果、构建日志和本次审查脚本。上一版失败证据没有覆盖。本轮首次完整回归的建图圈仍出现0.3秒停顿，原因是曲线计算仍在交接时执行；该次记录保留在 matrix-main，最终有效结果在 matrix-main-03 和 matrix-extra-03。

旧边界测试替身补齐新提取的 install_path 方法绑定，原25条断言不变；修改前失败记录保留在 static-before-fixture。

补充：识别点交接仍可能出现不足0.25秒的近零速瞬态；“额外停车为0”指按原完整转弯窗口检查未出现持续停顿，不代表每个采样时刻速度均非零。
