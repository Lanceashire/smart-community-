# 四项修复的严格验收方法（2026-10-04）

## 范围与冻结

按用户原始复赛资料保留 4.2×4.2 m 布局、人物与车牌素材、车辆及道路；本次世界新增灯态系统插件。模型仍为既有 YOLO11s，SHA256 见 `runtime-hashes.json`，本轮不训练、不改检测阈值。先保存 `before-source/`，冻结运行源码与实际加载的插件二进制，再运行同一版本的全部六圈。`acceptance-criteria.json` 保存开发时固定的门槛及第四次失败后追加的持续完赛要求；聚合只增加检查，没有放宽失败门槛。

## 四项改动

1. 灯态切换移入 Gazebo C++ 系统的 PreUpdate；同一仿真更新设置 12 个明/暗灯面，PostUpdate 检查实际 ECM 位姿。ROS 灯态节点只核验实际灯面、发布诊断，不再调用灯光服务。控制器仍只读取相机识别的灯态。插件延迟测量是仿真更新应用延迟，不能当作相机端到端延迟。
2. 修正转头时人物图像横坐标关联的方向。独立针孔投影验证几何关系。转动期间不累积身份确认，B_north 首个观察方向直接使用已验证几何位置；保留双实际角度、首角至少 5 帧、第二角至少 3 帧、角差至少 0.05 rad。
3. 从相机的红/黄/绿颜色变化建立绿灯开始时间区间，并由后续新鲜视觉重验证；在当前场景同步 10/15/3 秒时序内，连续 5 帧新鲜绿灯且剩余下界至少 3.2 秒即可放行。路口切换保留视觉相位记录、重置局部确认，避免在安全的已亮绿灯前重复等红灯。无视觉相位依据的冷启动绿灯，以及不足整车通行时间的晚绿灯，仍须等待。
4. 在最终版本上实际运行两种出生偏差、一次传感器扰动整圈。测试助手只扰动真实输入；真值只用于独立评分和测量断流时的实际速度，不向控制器提供位姿或识别答案。

## 圈次矩阵

`run_four_fixes_acceptance.py` 独占启动一套世界、结束后停止，再启动下一条件：

- main：正常一圈，再分别在新绿灯后墙钟 2 秒、6 秒重新开始，各一圈；重启时刻由验收工具控制，控制器不接收测试灯态。
- start-plus：出生 x/y 偏移 +2.5/-2.5 cm，航向 +0.035 rad。
- start-minus：出生 x/y 偏移 -2.5/+2.5 cm，航向 -0.035 rad。
- sensor-stress：图像高斯噪声 σ=3 灰度级，轮速里程计位置 σ=1 mm、航向 σ=0.001 rad，激光 xyz σ=5 mm，各流独立约 10% 丢消息。top_west 行驶时同时切断三流 2 仿真秒；1.5 秒后零控制命令且实际速度低于 0.015 m/s，恢复后完成整圈。种子 20261004。

偏差只改初始出生位姿，定位标称先验不变，行驶中不瞬移。新鲜定位样本的最大误差门限：正常 6 cm，出生偏差 10 cm，扰动 12 cm。断流内的过期定位另用“最后实测误差＋此后实际位移”三角不等式求保守上界，不把缺失样本填零；真值采样间隔须短于审计的 0.7 秒新鲜窗口，保证期间没有漏掉一个完整的新定位窗口。断流全段上界也须 ≤12 cm。不同启动相位的速度不能混成统一提升比例。

## 独立物理、视觉与信号核验

每圈须通过既有审计的全部条件：17 路点、8 个确认观察、8 居民与 2 访客、3 块正确车牌、整车道路边界违规采样为 0、两路口车头进入及车尾清线均为绿灯、结束停车且后续所有采样保持完成状态、终端事件与保存图像同帧框/姓名/置信度一一对应。独立 OCR 读取图片上的帧号，不能只相信节点自己的成功日志。

主三圈 B_north 必须零重试、每次不超过 6.5 仿真秒。六圈共 30 个人物观察均保留两实际角度。至少两次在已经亮着且足够安全的同一绿灯内放行，不经历新的红/黄，停止等待不超过 2 秒。逐次核对估计剩余下界不超过实际下一非绿时刻（容许 0.1 秒采样差），且下界满足 3.2 秒整车预算。

`observe_signal_integrity.py` 直接订阅 Gazebo 实际灯面位姿并与 ROS 只读状态比较。切换跨进程递送容许 0.3 墙钟秒，稳定段必须没有不一致，至少观察 12 次变化、100 次有效核对。插件实际 ECM 核验要求 12 灯面、至少 12 次应用、应用数与请求更新数一致、实际位姿全部匹配、零不一致、最大应用延迟不超过 2 仿真毫秒。

控制回归覆盖安全已绿放行、晚绿停行、冷启动未知绿不伪造相位、视觉断流清除局部帧数、相位过期重验证、时间倒退、实际控制回调继承及独立几何关联。与上一提交的 SDF 做独立 XML 结构比较，除新增插件外全部几何与素材引用须不变；新增插件、实际 GPU/YOLO/OCR 启动检查须通过。`summarize_four_fixes.py` 必须所有检查为 true 才返回 0。

## 失败尝试与证据边界

`attempt-01` 保留 B_north 仍重试的完整失败；`attempt-02-phase-freshness` 保留相位跨圈失效问题；`attempt-03-persistent-service-timeout` 保留持久连接仍超时的证据。`attempt-04-completion-status` 保留前五圈通过但干扰圈完赛状态被新鲜度检查覆盖的失败；修正完赛状态优先级，新增实际 tick 回调反例，然后整套六圈重新冻结运行。`attempt-05-image-verifier-timeout` 保存最终干扰圈独立图片 OCR 超时、仅限线程仍超时及局部文字检测失败。实际机器人六圈运行源码与二进制未变；改用同一 JPEG 左上帧号单行直接 OCR，保留全图 SHA256，原 90 秒门槛下完成全部图片核对；故意给错帧号的反例被拒绝。记录单独恢复后处理，不伪称原矩阵进程退出码为 0，也不计为新增巡航圈。上述尝试均不加入最终成功圈数。最终以 Gazebo 内部插件取代服务调用，不能只清零旧超时计数冒充解决。

完整原始采样、终端日志、事件图片仅在本机。GitHub 只保存源码、方法、门限和不含图片的数值汇总。本次结论限于资料给定布局、已知同步灯周期和上述扰动幅度，不能证明任意地图、陌生人物、不同灯周期或任意强噪声。原有暂停节点和实体障碍测试保留为历史版本证据，不冒称本次又重跑过。

## 复现

在 ROS/GPU 容器工程根目录，先构建并加载环境：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select sentry_motion_manager community_signal_system community_demo --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
source tools/ros_transport.sh
python3 tools/check_four_fixes.py
python3 tools/check_signal_handoff.py
python3 tools/check_reliability.py
```

先备份旧验收目录，避免覆盖历史数据。独立观察器单独终端运行，完成后用 Ctrl+C 保存报告：

```bash
python3 tools/observe_signal_integrity.py --duration 3600 --output validation/four-fixes-2026-10-04/signal-integrity.json
```

另一个终端运行矩阵，完成并停止观察器后聚合：

```bash
python3 tools/run_four_fixes_acceptance.py
python3 tools/summarize_four_fixes.py
```
